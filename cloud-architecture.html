Cloud Architecture

A proposed AWS architecture for the AI Student Help Desk System.

Architecture Proposal

Cloud-Based Multi-Agent AI Student Help Desk

The system provides a central support platform where students can ask questions, receive knowledge-base answers, create support tickets, and track ticket progress. Administrators and faculty can manage requests. In production, AWS services can provide hosting, authentication, database storage, document storage, access control, and monitoring.

1. Proposed AWS Architecture

This diagram shows the proposed production design. It is an architecture plan, not a live AWS deployment.

Users Student · Faculty · Admin · HOD · HOI
↓
Web Application HTML, CSS, JavaScript interface · Student and staff portals
↓
Amazon Cognito User sign-in, authentication, and token-based identity
↓
Backend API hosted on Amazon EC2 Receives requests, validates access, and coordinates application logic
↓
Multi-Agent Help Desk Logic Intent Recognition · Entity Extraction · Knowledge Retrieval · Decision · Ticket Management · Faculty Routing · Notifications
↓
Amazon RDS Structured records: students, tickets, replies, departments, knowledge metadata
Amazon S3 Documents, approved support files, and permitted attachments
↓
AWS IAM Controls permissions for AWS resources and services
Amazon CloudWatch Application logs, metrics, dashboards, and alarms

Production note: the backend should access RDS and S3 through appropriately restricted IAM permissions and secure network configuration. Users should not receive direct database credentials.

2. AWS Services and Their Responsibilities

Each service has a defined role in the proposed cloud deployment.

🖥️

Amazon EC2

Runs the backend application and API. It receives requests from the web interface and executes ticket, routing, and multi-agent logic.

Purpose: Backend hosting
🗂️

Amazon S3

Stores support documents, approved knowledge files, and permitted attachments. Access should be controlled rather than making private files public.

Purpose: Document storage
🛢️

Amazon RDS

Stores structured application data such as users, departments, tickets, ticket replies, notifications, and knowledge-base metadata.

Purpose: Relational database
🔐

Amazon Cognito

Provides user sign-up and sign-in capabilities. The application can use authenticated identity and tokens to protect API requests.

Purpose: Authentication
🛡️

AWS IAM

Defines permissions for AWS users, roles, and services. Separate permissions should be used for backend access, storage, monitoring, and administration.

Purpose: Access management
📈

Amazon CloudWatch

Collects logs and metrics, supports dashboards, and can trigger alarms for errors or unusual resource usage.

Purpose: Monitoring

3. Student Request Flow

Example: a student asks about a semester examination and may need to create a support ticket.

Step Component Activity
1 Student Web Portal The student signs in and enters a question in the chatbot.
2 Amazon Cognito The production application verifies the student's identity.
3 EC2 Backend API The backend receives the request and checks the user's access.
4 Intent and Entity Agents The system identifies the topic, such as examination, and extracts details such as “hall ticket.”
5 Knowledge Retrieval Agent The system searches approved knowledge-base content for a relevant answer.
6 Decision Agent If a suitable answer is available, the chatbot returns it. Otherwise, it can ask for clarification or offer ticket creation.
7 Ticket Management Agent If the student creates a ticket, the backend saves it in Amazon RDS.
8 Faculty Routing / Notification The ticket is routed according to department rules, and relevant notifications are generated.
9 CloudWatch Application events, errors, and operational metrics can be monitored.

4. Data Storage Design

Use a relational database for structured records and object storage for files.

Data Proposed storage Example fields or content
Students and staff Amazon RDS User ID, name, email, role, department
Support tickets Amazon RDS Ticket ID, student ID, subject, category, status, priority, assigned staff
Ticket replies Amazon RDS Reply ID, ticket ID, sender, message, timestamp
Notifications Amazon RDS Notification ID, recipient, message, read status, timestamp
Knowledge-base records Amazon RDS Article ID, title, category, approval status, S3 object reference
Documents and attachments Amazon S3 Approved PDFs, help documents, permitted ticket attachments
Store file references and related metadata in the database. Keep the actual files in S3. Apply access controls and avoid storing unnecessary personal information.

5. Security and Access Control

Security should be applied at the login, API, data, and monitoring layers.

Authentication and authorization

  • Use Amazon Cognito for user authentication in production.
  • Verify authenticated requests in the backend.
  • Check role and department permissions before allowing actions.
  • Students should only access their own tickets and permitted records.
  • Faculty and administrators should receive only the access required for their roles.

AWS resource protection

  • Use IAM roles and least-privilege permissions for AWS resources.
  • Keep database access restricted to the backend.
  • Protect stored documents with appropriate S3 access policies.
  • Use secure connections and protect application secrets.
  • Monitor errors and access-related events using CloudWatch.
