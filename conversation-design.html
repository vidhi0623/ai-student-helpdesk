Conversation Design

Chatbot flow, sample dialogue, and multi-agent responsibilities.

Conversation Blueprint

Student Help Desk Chatbot

Conversation design defines how the chatbot greets students, understands their questions, asks clarifying questions, retrieves approved information, and offers ticket creation when needed. The chatbot should communicate clearly, avoid guessing, and explain the next step to the student.

1. Conversation Flow

The flow below describes the intended chatbot conversation, including answer retrieval and ticket escalation.

1. Student opens the chatbot The chatbot starts a new support conversation.
↓
2. Greeting and question The bot greets the student and asks how it can help.
↓
3. Intent Recognition + Entity Extraction Identify the topic and important details in the student's message.
↓
4. Knowledge Retrieval Search the approved knowledge base for a relevant answer.
↓
Suitable answer found Show the answer and ask whether it helped.
No suitable answer Ask a clarifying question or offer ticket creation.
↓
Student is satisfied End the conversation politely.
Student needs more help Collect the details required to create a support ticket.
↓
5. Ticket creation and routing Save the ticket, identify the responsible department, and notify the relevant team.
↓
6. Confirmation and tracking Show the ticket ID and direct the student to My Tickets.
If the student's request is unclear, the chatbot should ask a short clarifying question instead of inventing an answer.

2. Sample Conversation: Semester Examination

Example dialogue for a student asking about an examination hall ticket.

Chatbot Hello! Welcome to the AI Student Help Desk. How can I help you today?
Student I have a question about my semester examination.
Chatbot I can help with that. Is your question about the exam timetable, hall ticket, examination rules, or result?
Student Hall ticket.
System process Intent identified: Examination · Entity identified: Hall ticket
Chatbot Please check the examination section of your student portal for hall-ticket information. If you cannot find it or need further help, I can create a support ticket.
Student I still need help. Create a ticket.
Chatbot Sure. Please provide a short description of the issue and confirm the department if it is not already identified.
Student I cannot find my hall ticket. Examination department.
System process Ticket details are prepared and saved after the student confirms.
Chatbot Your support ticket has been created. You can view its status and replies in the My Tickets section.

3. Multi-Agent Responsibilities

Each agent performs a focused task within the overall help desk conversation.

01

Intent Recognition Agent

Determines the student's main request, such as examination, fees, scholarship, placement, library, hostel, or login help.

02

Entity Extraction Agent

Extracts useful details such as semester, subject, department, ticket number, or the specific service mentioned.

03

Knowledge Retrieval Agent

Searches approved help articles and returns relevant information for the chatbot to present.

04

Decision Agent

Decides whether to show an answer, ask a clarification, or offer escalation to a human support team.

05

Ticket Management Agent

Creates and updates support tickets, maintains status, and makes ticket details available to authorized users.

06

Faculty Routing Agent

Routes a ticket to the appropriate department or assigned faculty member using configured routing rules.

07

Email Notification Agent

Sends or prepares notifications about ticket creation, assignment, replies, and status changes.

08

Learning / Knowledge Update Agent

Identifies useful unresolved questions for review. New knowledge should be approved before being published.

09

Analytics Agent

Summarizes ticket volume, categories, response patterns, and common unresolved issues for authorized staff.

4. Clarification and Fallback Rules

These rules help keep the chatbot useful when a message is incomplete or the knowledge base has no matching answer.

Situation Chatbot response Next action
Question is too broad Ask the student to select or specify the topic. Run intent recognition again after clarification.
Required detail is missing Ask one focused question, such as which semester or department. Use the additional detail to search or route the request.
No relevant knowledge article Explain that a suitable answer was not found. Offer ticket creation or human support.
Student is not satisfied Ask whether they want to explain the issue further or create a ticket. Continue the conversation or escalate.
Ticket details are incomplete Ask for the missing required information before submission. Show a confirmation before saving the ticket.

5. Conversation Design Principles

The chatbot should make each interaction understandable, consistent, and easy to complete.

Principle How it is applied
Clear language Use short sentences and familiar student-support terms.
One question at a time Ask only for the detail needed to continue the current step.
Transparent responses Do not claim that a ticket was created unless it was actually saved.
Human escalation Provide a ticket or staff-support option when the bot cannot resolve the issue.
Privacy Request only information required for support and restrict access to ticket details.
Consistent confirmation After ticket creation, show the ticket ID and explain how to track it.
The dialogue on this page is a design example. It does not automatically run inside the existing chatbot page unless the chatbot logic is separately connected to these flows.
